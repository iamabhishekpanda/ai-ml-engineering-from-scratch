# Azure Observability

> Turn model quality, system health, and user impact into signals that an operator can act on.

**Type:** Build
**Languages:** Python
**Prerequisites:** Debugging & Profiling, Azure Container Apps
**Time:** ~60 minutes

## Learning Objectives

- Distinguish logs, metrics, traces, and evaluation records.
- Define correlation ids across API, retrieval, model, and tool calls.
- Set alerts on latency, errors, cost, and quality drift.
- Remove secrets and sensitive content from telemetry.
- Write an incident response signal map.

## Practice

Use `code/main.py` to validate an observability plan. A trace is useful only when it connects a user request to a measurable decision.
